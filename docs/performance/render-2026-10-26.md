# Render performance investigation — 2026-10-26

Baseline: `793481ee9dcba407f06fe328410e3cc689a688ad` (PR #162 merged).

## Findings

The reported symptom is a formerly stable 60 FPS becoming variable below 50 FPS
in ordinary missions. A software benchmark cannot establish the live GPU/driver
cause or guarantee the final frame rate.

Moving the HUD below combat does not draw enemies twice. With an identical
fixed game state, 160 drawings of each version produced exactly 160 formation
draw calls. Median draw_play times in milliseconds:

| Stage | Before the layer change | Current layer order |
| --- | ---: | ---: |
| Birds | 0.2382 | 0.2328 |
| Gargoyles | 0.3367 | 0.3237 |
| Boss | 0.6921 | 0.6876 |

These are CPU microbenchmarks, not displayed FPS. They do not reproduce a large
regression from layer order alone.

Two avoidable costs were found:

1. The new announcement translucency copies the text, plate and halo on every
   frame, including when the same opacity variant has just been used.
2. The CPU presentation path can clear the whole output window twice before
   covering it with an opaque full-window picture.

## Changes

Opacity variants of immutable cached announcement text/plates now use a bounded
LRU cache: at most 96 entries and 4 MiB of variant pixel storage. The source
surfaces remain unchanged. On the repeated pulsing-banner benchmark, 1,050
surface copies over 360 drawings became zero after warmup; median drawing time
went from 0.7060 to 0.6577 ms.

Black clears are skipped only for an opaque full-window presentation with no
shake and an up-to-date viewport. Shake, bezels, letterboxing, alpha/colour-key
canvases and stale layout keep the existing safe path. Direct drawing remains
restricted to the SCALED backend. CPU presentation microbenchmark, including
the former two fills:

| Output | Before, median ms | After, median ms |
| --- | ---: | ---: |
| 1920 × 1080 | 4.4819 | 2.9823 |
| 2560 × 1440 | 6.8032 | 4.0574 |
| 3840 × 2160 | 18.0002 | 13.6746 |

## Validation and limits

Measured with Python 3.13, Pygame 2.6.1 and SDL's dummy display, not the player's
real GPU presentation. Timing depends on machine load; the 4K CPU fallback is
still expensive. No FPS limit, VSync preference, resolution, CRT setting,
particle count, animation timing or HUD/enemy layer order was changed.

- 52 integration/render checks passed with saves kept in RAM and local writes blocked.
- Pixel comparisons cover CPU presentation at 720p/1080p/1440p, opaque/alpha
  canvases and screen shake, plus existing direct-draw tests.
- 45 announcement comparisons (three sizes, five fade levels, three glows)
  match the previous RGB pixels exactly.
- The 2,400-frame hot-seat fuzz replay matches its existing gameplay reference.
- Full GitHub CI remains required.

CRT levels 2–3 cost several milliseconds in this software environment. NumPy
lookups, alternative SDL blend flags and batched CRT blits were benchmarked and
rejected because they were slower. RLE opacity variants changed pixels and were
also rejected. The existing CRT image is preserved.
